# Introduce email verification-code authentication and owner bootstrap

## Why

Every other 0.1.0 capability needs users, sessions, and exactly one initial
Owner. Self-hosted instances have no SMTP guarantee, so login must work with
zero external identity infrastructure while leaving room for a delivery
provider later.

## What Changes

- Email + verification-code signup/login: codes are generated by the backend,
  short-lived, single-use, and delivered through backend logs for 0.1.0.
- Successful verification issues an HTTP-only authenticated session cookie.
- First account on a fresh instance becomes Owner atomically; all later
  accounts become Requester (role model itself lands in
  introduce-role-and-permission-model).
- Code delivery sits behind a small interface so an email provider can be
  added without changing authentication semantics.
- First SQL migrations (users, verification codes, sessions, instance owner
  claim) applied from `migrations/`.

Explicitly out of scope: SMTP, OAuth/OIDC/SSO, passwords or password reset,
third-party identity providers, email-change flows.

## Capabilities

### New Capabilities

- `email-auth`: verification-code issuance/verification, session lifecycle,
  first-owner atomic bootstrap.

### Modified Capabilities

(none)
